## What Is a Security Agent Harness

A security agent harness is everything wrapped around the model: the sandbox it runs in, the analysis tools it can call, the prompts and skills that encode a methodology, and the evals you use to check it. Most of the engineering lives here rather than in the model, or as Cloudflare put it after scaling one across its own fleet, the harness is the bit that lasts.

Agents are good at producing plausible findings and bad at telling which ones are real. An agent will edit the source so its own exploit works, then report the bug it just created. So the metric that matters is not recall, which nobody can measure without already knowing every bug in a codebase, but how few unconfirmed findings reach a human: Cloudflare's pipeline cut 20,799 raw candidates down to 12,057 that survived validation, then folded away another 5,442 as duplicates. A harness that can reproduce a crash, replay an input, or re-run a static analyzer is how you throw out the bad ones before a human ever sees them.

Entries tagged `SKILL.md` are skill packs rather than runnable harnesses: methodology encoded as [Agent Skills](https://agentskills.io) that a general coding agent like Claude Code executes. They live in the section matching what they do.

The same holds on defense. An AI SOC agent writes plausible verdicts and plausible detections, and the harness is what checks them: replaying a detection against captured telemetry, demanding cited evidence before an alert is closed, or scoring the defender against an attacker whose actions are already known. Attack-defense setups make the attacker that answer key.

## Code Audit Harnesses

Harnesses that run coding agents against source code: discovery, triage, validation, and patching.

- [0 Security](https://github.com/0sec-labs/0) - Security harness with a local web console for vulnerability research, verification, and fixes, exposing the same reusable workflows through CLI and MCP.
- [Anthropic Defending Code Reference Harness](https://github.com/anthropics/defending-code-reference-harness) - Reference implementation for autonomous vulnerability discovery and remediation with Claude, with skills for threat modeling, scanning, triage, and patching.
- [audit](https://github.com/evilsocket/audit) - Eight-stage discovery agent built on the Claude Code SDK, combining many narrow agents, deliberate disagreement between them, and an explicit reachability gate.
- [Capital One VulnHunter](https://github.com/capitalone/VulnHunter) - Agentic security tool applying proactive, attacker-first analysis directly to source code.
- [Clearwing](https://github.com/Lazarus-AI/clearwing) - Autonomous source-code hunter that ranks files, fans out specialist agents, and treats sanitizer crashes as ground truth, with a separate network-pentest mode.
- [Cloudflare Security Audit](https://github.com/cloudflare/security-audit-skill) - Six-phase audit skill: parallel hunting agents attack the codebase from different angles, separate agents try to disprove each finding, and fresh agents verify the schema-validated `findings.json` against source. `SKILL.md`.
- [GitHub Security Lab Taskflow Agent](https://github.com/GitHubSecurityLab/seclab-taskflow-agent) - YAML framework that runs security workflows as chains of small tasks, each in a fresh context, passing notes through a database and handing deterministic checks to MCP tools; GitHub Security Lab reports about 30 real vulnerabilities from its CodeQL alert-triage taskflows and publishes companion taskflows for app audits and AFL++ fuzzing.
- [Google Mantis](https://github.com/google/mantis) - Modular, stack-agnostic toolkit of security review skills for coding agents to find, reproduce, and patch vulnerabilities, with gVisor-sandboxed reproducers and an explicit false-positive filter rule.
- [Hadrian OpenHack](https://github.com/hadriansecurity/OpenHack) - File-based workflow run inside Claude Code, Codex, or Cursor that scopes each unit of agent work to one routing unit, one of 12 expert families, and one proof question, then sends every finding candidate to a separate triage agent; Hadrian reports that a more advanced internal version surfaced hundreds of vulnerabilities in a dozen open-source applications used by Dutch government agencies.
- [Krait](https://github.com/ZealynxSecurity/krait) - Claude Code audit methodology for Solidity with 101 heuristics, 26 analysis modules, and 8 kill gates that try to disprove every finding, measured blind on 50 Code4rena contests at 100% precision on the v8 baseline.
- [Open Kritt](https://github.com/Kritt-ai/open-kritt) - Self-hosted orchestrator that runs agents to find and validate vulnerabilities, export canonical findings, and rank severity, with bug-bounty payouts credited to its Blockian researcher identity.
- [OpenAI Codex Security](https://github.com/openai/codex-security) - CLI and TypeScript SDK for finding, validating, and fixing security vulnerabilities with Codex.
- [OpenAnt](https://github.com/knostic/OpenAnt) - Source-code auditing pipeline that decomposes repositories into analysis units, offers adversarial verification of candidate findings, and can run Docker-isolated dynamic tests before reporting.
- [OpenHack](https://github.com/openhackai/OpenHack) - Multi-agent scanner running recon, specialist hunts, independent validation, and sandbox and browser verification, using only open-source models.
- [RAPTOR](https://github.com/gadievron/raptor) - Autonomous research framework chaining static analysis, binary analysis, vulnerability validation, exploit generation, and patch writing over a codebase or binary. `SKILL.md`.
- [rust-in-peace](https://github.com/scadastrangelove/rust-in-peace) - Vulnerability research harness for Rust with independent review passes, adversarial triage, dynamic verification, and an experimental Android APK analysis profile.
- [Trail of Bits Skills](https://github.com/trailofbits/skills) - Skills for security research, vulnerability detection, and audit workflows, distilled from the firm's audit practice. `SKILL.md`.
- [Vercel Labs Deepsec](https://github.com/vercel-labs/deepsec) - Security harness for finding vulnerabilities in a codebase using coding agents.
- [Visa Vulnerability Agentic Harness](https://github.com/visa/visa-vulnerability-agentic-harness) - Agentic SAST pipeline for autonomous vulnerability discovery, remediation, and validation, emitting Markdown and SARIF reports.

## Pentesting Agents

Agents that attack running applications and infrastructure: reconnaissance, exploitation, and proof of impact.

- [AIDA](https://github.com/Vasco0x4/AIDA) - Model-agnostic pentesting agent that reasons over a defined scope, executes in an isolated container, and keeps persistent assessment state across sessions.
- [ARTEX](https://github.com/BaaRai/ARTEX) - Go multi-agent pentest system in which a planner keeps a todolist across wake-ups and dispatches intents to parallel workers, which record facts and findings on a per-task exploration graph linked to a shared asset graph. Microsoft, Datadog, and Unit 42 have reported it used in real intrusions. The link is a maintained English-language fork; the original author made the project closed-source in October 2026.
- [AWE](https://github.com/stuxlabs/AWE) - Research framework pairing a lightweight orchestration layer with memory-augmented, vulnerability-specific agent pipelines, evaluated on the XBOW benchmark.
- [BlacksmithAI](https://github.com/yohannesgk/blacksmith) - Multi-agent pentesting framework that walks a target from reconnaissance through post-exploitation inside a Docker image preloaded with standard security tooling, driven from either a web UI or a CLI.
- [BreachWeave](https://github.com/m-sec-org/BreachWeave) - Multi-role pentest harness where a Manager schedules and reclaims Solvers that exploit in parallel while a bystander Observer watches for drift and holds the termination decision, built on the Pi SDK; placed first of 613 teams in both the online and offline rounds of the second Tencent Cloud AI pentest challenge.
- [BugTraceAI](https://github.com/BugTraceAI/BugTraceAI) - Multi-agent platform for authorized web application security testing with independent validation, evidence capture, and reporting.
- [CAI](https://github.com/aliasrobotics/cai) - Alias Robotics' framework for building cybersecurity agents, with tool and workflow primitives for offensive testing.
- [Cairn](https://github.com/oritera/Cairn) - Pentesting as state-space search: Claude Code, Codex, or Pi workers with no fixed roles coordinate only through a blackboard of facts, intents, and hints, and solved all 54 problems at the Tencent Cloud AI pentest challenge, the only team to clear the board.
- [Chain Reactors Cyber Harness](https://github.com/chainreactors/cyber-harness) - Go harness assembling scanning, terminal tools, browser automation, and subagents through a shared extension lifecycle, with entry points for pentesting and source-code or binary audits.
- [CHYing-agent](https://github.com/yhy0/CHYing-agent) - Human-AI teaming pentester with an orchestrator coordinating command-execution, browser, C2, and reverse-engineering subagents over Kali, rebuilt on the Claude Code Python SDK; the ninth-place finisher in the first Tencent Cloud AI pentest challenge.
- [Cochise](https://github.com/andreashappe/cochise) - Minimal Active Directory pentesting harness with separate planning and execution, persistent knowledge, and replayable trajectories, released with GOAD evaluation documentation.
- [CyberStrike](https://github.com/CyberStrikeus/CyberStrike) - Offensive-security harness coordinating autonomous agents over signed attack skills, built-in tools, and MCP integrations, mapped to MITRE ATT&CK and OWASP WSTG.
- [Dark-Moon](https://github.com/ASCIT31/Dark-Moon) - Open-source (GPLv3) autonomous AI penetration-testing CLI coordinating 50 specialist agents and 140+ offensive tools over MCP, with a dedicated LLM-security agent for the OWASP LLM Top 10; runs on a local (Ollama/llama.cpp) or cloud LLM.
- [hackingBuddyGPT](https://github.com/ipa-lab/hackingBuddyGPT) - TU Wien research framework for writing LLM pentesting agents in roughly 50 lines of code, released alongside reusable Linux privilege-escalation benchmarks and open-access evaluations.
- [HPTSA](https://github.com/uiuc-kang-lab/HPTSA) - Research implementation behind *Teams of LLM Agents can Exploit Zero-Day Vulnerabilities*, using a supervisor agent to coordinate vulnerability-specialized subagents.
- [Incalmo](https://github.com/cylabcyberautonomy/Incalmo) - Multi-host network pentesting framework separating high-level attack actions from low-level execution, with shared environment state, attack-graph services, and an MHBench integration.
- [LuaN1aoAgent](https://github.com/SanMuzZzZz/LuaN1aoAgent) - Autonomous pentester built on causal graph reasoning, splitting Planner, Executor, and Observer roles over durable events and evidence-backed graph memory; the BinX team's third-place project from the first Tencent Cloud AI pentest challenge, since rewritten on TypeScript and the Pi SDK.
- [Nebula](https://github.com/berylliumsec/nebula) - Penetration-testing assistant that automates recon, note-taking, and tool orchestration.
- [NeuroSploit](https://github.com/Red-Team-Leaders/NeuroSploit) - Rust harness that turns a URL, repository, or host into an autonomous engagement, selecting only the specialist agents matching the surface and validating findings across models.
- [PentAGI](https://github.com/vxcontrol/pentagi) - Fully autonomous multi-agent pentesting system with Docker isolation, planning and supervision, persistent memory, and a web control plane.
- [Pentest Copilot](https://github.com/bugbasesecurity/pentest-copilot) - Agent that drives a Kali attack box end to end, installing tooling as needed, operating Burp and a real browser, and spawning parallel subagents.
- [Pentest Swarm AI](https://github.com/Armur-Ai/Pentest-Swarm-AI) - Go harness coordinating recon, classification, exploitation, and reporting agents through a shared pheromone blackboard, waking each agent by finding weight rather than a fixed pipeline order.
- [PentestAgent](https://github.com/GH05TCREW/pentestagent) - Black-box testing framework with autonomous and multi-agent modes, attack playbooks, Kali execution, and persistent sessions.
- [PentestCode](https://github.com/s0ld13rr/pentestcode) - Hard fork of OpenCode rebuilt for offense, coordinating a lead strategist and parallel specialist subagents over shared engagement state, with attack-path search across a relationship graph and persistent sessions.
- [PentestGPT](https://github.com/GreyDGL/PentestGPT) - Automated penetration-testing agentic framework powered by large language models.
- [RedAmon](https://github.com/samugit83/redamon) - End-to-end platform chaining recon, exploitation, and post-exploitation over a Neo4j attack graph, then triaging findings, patching the code, and opening pull requests.
- [reverse-skill](https://github.com/zhaoxuya520/reverse-skill) - Security skill router that guides coding agents through repeatable reverse-engineering and penetration-testing workflows with tool bootstrapping and evidence tracking. A recent [Tessl review](https://tessl.io/registry/skills/github/zhaoxuya520/reverse-skill/reverse-skill-router) scored its primary router 75/100 (92% quality), with no impact evaluation and a failed security scan. `SKILL.md`.
- [Shannon](https://github.com/KeygraphHQ/shannon) - AI pentester for web applications and APIs that analyzes source code, identifies attack vectors, and executes real exploits to prove findings.
- [Strix](https://github.com/usestrix/strix) - Open-source AI penetration-testing agent that finds and helps fix application vulnerabilities.
- [Transilience Community Tools](https://github.com/transilienceai/communitytools) - Twenty-six skills and three tool integrations covering the pentest lifecycle from recon to reporting, with a published 104/104 result on the maintainers' CTF benchmark. `SKILL.md`.
- [Vulnerator AI](https://github.com/irraz/vulnerator-ai) - Autonomous OODA pentest agent driven by Hermes (Nous Research) that drives Kali tooling directly over an MCP server.

## Fuzzing and Vulnerability Discovery

Harnesses that use models to find crashes and generate patches.

- [ChatAFL](https://github.com/ChatAFLndss/ChatAFL) - Protocol fuzzer built on AFLNet that prompts a model for a machine-readable grammar, for richer seed messages, and for new inputs whenever coverage plateaus, published at NDSS 2024 and packaged as a ProfuzzBench artifact.
- [Creation](https://github.com/AntAISecurityLab/Creation) - Ant Group's harness plus a 27B model post-trained from Qwen 3.8, splitting a solving agent from a judge-gated submission cascade; self-reports crashes on the vulnerable build only for 1,484 of 1,507 CyberGym Level 1 tasks.
- [FirmAgent](https://github.com/vul337/FirmAgent) - Hybrid IoT firmware pipeline from Tsinghua's VUL337 group, pairing a device-aware API fuzzer with an LLM taint-analysis agent that turns sink-reaching findings into proof-of-concept exploits, published at NDSS 2026.
- [Fuzz4All](https://github.com/fuzz4all/fuzz4all) - Universal fuzzer using a model as its input generation and mutation engine, with an autoprompting step that tunes the prompt per target so one tool covers many input languages, from the ICSE 2024 paper.
- [GitHub Security Lab Fuzzing Taskflows](https://github.com/GitHubSecurityLab/seclab-taskflows-fuzzing) - AFL++ pipeline for C/C++ projects on the Taskflow Agent: 11 stages, three builds per harness (ASan and UBSan, CmpLog, coverage), and time budgets that double from 30 seconds until coverage plateaus; it runs model-chosen build commands on the host, so use a disposable machine.
- [OSS-Fuzz-Gen](https://github.com/google/oss-fuzz-gen) - Google's framework for generating and benchmarking fuzz targets with LLMs across C/C++, Java, and Python.
- [PortSwigger HTTP Terminator](https://github.com/PortSwigger/http-terminator) - HTTP desync research pipeline that splits 138 RFCs into 15,000 short fragments to prompt for 30,000 unique triggers, tests them against authorized live sites through a Burp extension, and hands hits to exploitation agents whose success is judged by validation code they cannot modify; reported about 700 vulnerable targets and an Apache Traffic Server zero-day (CVE-2026-63078).
- [PromptFuzz](https://github.com/FuzzAnything/PromptFuzz) - Fuzz-driver generator that mutates prompts in a coverage-guided loop to explore complex API interrelationships, reporting 40.12% branch coverage on its tested libraries, 1.61x OSS-Fuzz's, and 33 confirmed security bugs including three CVEs.
- [QuartetFuzz](https://github.com/OwenSanzas/QuartetFuzz) - Agent pipeline that generates fuzz harnesses under quality gates derived from four source-level principles, ending in adversarial validation before submission, released with a 100-case gold-harness dataset for measuring generated harnesses.
- [Ultrafuzz](https://github.com/monad-developers/ultrafuzz) - Monad's agentic orchestrator for smart-contract fuzzing and threat hunting that runs specialized agents over a protocol repo and collects generated fuzz tests and findings, with an EVMBench integration and a published longitudinal eval suite.

## DARPA AIxCC Cyber Reasoning Systems

The seven finalist systems from the DARPA AI Cyber Challenge, each built to autonomously find and patch vulnerabilities in real open-source code, and each released as a competition snapshot.

- [ARTIPHISHELL](https://github.com/shellphish/artiphishell) - Shellphish's cyber reasoning system, released with its components, pipelines, services, and full deployment stack.
- [Atlantis](https://github.com/Team-Atlanta/aixcc-afc-atlantis) - Team Atlanta's cyber reasoning system that won the final competition.
- [BugBuster](https://github.com/42-b3yond-6ug/42-b3yond-6ug-crs) - Team 42-b3yond-6ug's cyber reasoning system, preserved with the core components and deployment configuration needed to run it.
- [Buttercup](https://github.com/trailofbits/buttercup) - Trail of Bits' second-place cyber reasoning system, pairing an OSS-Fuzz fuzzing campaign with a multi-agent patcher.
- [FuzzingBrain](https://github.com/fuzzingbrain/afc-crs-all-you-need-is-a-fuzzing-brain) - Team all_you_need_is_a_fuzzing_brain's system, pairing coverage-guided fuzzing with agents that reason about suspicious points, build proofs of vulnerability, and dynamically verify every finding.
- [Lacrosse](https://github.com/siftech/afc-crs-lacrosse) - SIFT's multi-agent cyber reasoning system, combining fuzzing and symbolic reasoning to find and patch bugs in C and Java.
- [Robo Duck](https://github.com/theori-io/aixcc-afc-archive) - Theori's third-place cyber reasoning system, released as the complete finals submission.

## AI SOC and Autonomous SOC Agents

Agents that do security operations work against real telemetry: alert triage, investigation, threat hunting, detection engineering, and response.

- [Agentic Detection Engineering Framework](https://github.com/Nebulock-Inc/agentic-detection-engineering-framework) - Nebulock's CLI and MCP server that wraps an existing rule repository in a per-detection journal and a five-stage Find, Observe, Refine, Govern, Evolve lifecycle, so every threshold change and retirement an agent proposes carries a dated reason; it reads the repo, never writes to it, and never connects to the SIEM.
- [Agentic SOC Platform](https://github.com/FunnyWolf/agentic-soc-platform) - Streams SIEM and webhook alerts into correlated cases, runs LLM investigation and threat-intel enrichment inside the same playbook system as conventional SOAR steps, and exposes its capabilities to Claude Code, Codex, and other coding agents.
- [AI_SOC](https://github.com/zhadyz/AI_SOC) - Local research SOC combining Wazuh-format ingestion, flow classification, Ollama-based triage over retrieved security knowledge, incident correlation, analyst review, and Sigma rule export, with a disposable Wazuh lab for testing response actions and rollback.
- [AiSOC](https://github.com/beenuar/AiSOC) - Open-source AI SOC with alert fusion, LLM-agent triage, MITRE ATT&CK-mapped investigation, and a replayable decision log.
- [Argus](https://github.com/Sec-Link/Argus-Agentic-SOC-Platform) - API-first agentic SOC platform covering AI investigation, alert and incident management, workflow automation, threat-intel enrichment, and asset context, deployable standalone or beside an existing stack.
- [kodeblue](https://github.com/Problem99-io/kodeblue) - One agent per Linux server that learns the host's baseline with deterministic zero-token sensors, sends only what survives them to a small model for triage, contains attacks when policy allows, and retunes its own detections daily.
- [SamiGPT](https://github.com/M507/AI-SOC-Agent) - Investigation and incident-response platform exposing case management, SIEM queries, and threat-intel enrichment to agents over MCP, released with its Black Hat MEA 2025 talk.
- [SecurityClaw](https://github.com/SecurityClaw/SecurityClaw) - Skill-based autonomous SOC agent that watches OpenSearch or Elasticsearch data, builds a RAG-based memory of normal behavior, and has a model validate anomalies as they arrive.
- [SHERLOCK](https://github.com/ThalesGroup/sherlock-threathunting-tool) - Thales's threat-hunting agent that turns a hypothesis or campaign name into sourced IOCs, runs queries across Microsoft Sentinel, Microsoft Defender, and Google SecOps, and reports a timeline; no write or response tool exists in the codebase, so read-only is enforced by construction rather than by prompt.
- [SocTalk](https://github.com/soctalk/soctalk) - Wazuh-native triage agent that routes each alert through a two-tier LLM pipeline, auto-closes cases when policy allows, and keeps a human on escalations and gated actions, for one team or a multi-tenant MSSP.
- [Vigil](https://github.com/Vigil-SOC/vigil) - Apache-2.0 AI SOC that runs against your own local or remote model, from the DeepTempo team behind the SOCBench benchmark.

## Purple Team and Red vs Blue Harnesses

Attacker and defender agents run against each other or feed each other: attack-defense arenas, emulation that turns attacks into ground truth for detections, and LLM blue agents in cyber-defense gyms.

- [Ares](https://github.com/dreadnode/ares) - Dreadnode's Rust platform pitting an LLM red orchestrator and seven Active Directory attack workers against a blue orchestrator whose SOC workers query Loki and Prometheus and write detections back to Grafana; red's verified final state becomes blue's scoring rubric, and a replay mode snapshots a run's telemetry so each prompt change is rescored against the same attack and checked on a held-out set.
- [ARTEX Defense](https://github.com/ja1sh/artex-defense) - Sigma pack and offline purple-team test harness for the behavior of ARTEX, the attacker harness seen in real intrusions: seven behavioral rules, five correlations, and two fingerprints, each with fixtures, telemetry requirements, and a validation playbook.
- [AutomatedEmulation](https://github.com/iknowjason/AutomatedEmulation) - Terraform-built Caldera adversary-emulation lab with an MCP server, so a model can author Caldera techniques and operations against instrumented hosts.
- [Caldera MCP](https://github.com/mitre/mcp) - MITRE's Caldera plugin that runs long LLM workflows to generate adversary-emulation abilities and plan operations.
- [llms-are-acd](https://github.com/r4wd3r/llms-are-acd) - Adapter that turns CybORG CAGE 4 observations into text for LLM blue agents and mixed LLM and RL defender teams, from the paper *Large Language Models are Autonomous Cyber Defenders*, where RL baselines still beat the LLMs on CAGE reward.
- [NeuroPurple](https://github.com/JoasASantos/NeuroPurple) - Defensive inversion of NeuroSploit that reuses the offensive engine as ground truth for detection engineering, rewarding coverage gained minus time to detect minus a heavy false-positive penalty, and growing its own playbook library.
- [OpenClaw AWD Arena](https://github.com/LYiHub/OpenClaw-AWD-Arena) - Attack-with-defense platform where several LLM agents attack each other's services and patch their own in timed rounds, with a referee engine for scoring and a live spectator UI; documentation in Chinese.

### Deception Against Attacker Agents

Honeypots and lures built to catch, slow, or turn LLM-driven attackers.

- [AlterHive](https://github.com/Fausto-404/AlterHive) - High-interaction deception platform, documented in Chinese, that leads attackers and pentest agents into a shadow subnet expanded on the fly from their apparent intent, using a virtual topology, session memory, and multi-agent deception planning.
- [Beelzebub](https://github.com/beelzebub-labs/beelzebub) - Decoy framework where services, routes, and responses are defined in YAML and answered by static handlers or a model, capturing each interaction as evidence.
- [Blacksea](https://github.com/cracken-ai/blacksea) - Active honeypot and canary-bait system that detects LLM-driven attackers and exploits flaws in their judgment to get code execution on the attacker's own machine; listed as the code for *Red-Teaming the Agentic Red-Team*.
- [DECEIVE](https://github.com/Cisco-Talos/DECEIVE) - Cisco Talos's SSH honeypot where a model simulates the entire Linux server from a plain-language system description, then logs, summarizes, and judges each session.
- [LLM Honeypot](https://github.com/PalisadeResearch/llm-honeypot) - Palisade Research's Cowrie SSH honeypot that hides prompt-injection traps in common command output to make LLM agents reveal themselves and their instructions, with a public dashboard and paper.

## Agent Tooling and Integrations

Security capabilities exposed to somebody else's agent: MCP servers, disassembler plugins, and broad skill libraries. These supply the tools and methodology a harness calls; they do not own the agent loop themselves.

- [Anthropic-Cybersecurity-Skills](https://github.com/mukul975/Anthropic-Cybersecurity-Skills) - Community library of 800+ skills across 29 security domains, mapped to MITRE ATT&CK and NIST CSF; not affiliated with Anthropic despite the name. `SKILL.md`.
- [Arkana](https://github.com/JameZUK/Arkana) - MCP server putting 308 binary-analysis tools behind one prompt, including angr decompilation, symbolic execution, and data- and control-dependency queries, plus signature engines, emulation, and interactive debugging with snapshots.
- [Binary Ninja Headless MCP](https://github.com/mrphrazer/binary-ninja-headless-mcp) - Headless Binary Ninja MCP server exposing 180 analysis tools to agents.
- [Burp Suite MCP](https://github.com/PortSwigger/mcp-server) - PortSwigger's own MCP server, connecting agents to Burp Suite's proxy, scanner, and repeater.
- [Claude Code CyberSecurity Skills](https://github.com/Masriyan/Claude-Code-CyberSecurity-Skill) - Nineteen skills spanning offensive security, defensive operations, reverse engineering, threat hunting, and SOC automation. `SKILL.md`.

## Readings

Writing that has shaped how these harnesses get built. Same bar as the tools: results, not takes.

- [1Password: Detection Engineering Meets AI-Driven Adversary Emulation](https://1password.com/blog/ai-driven-adversary-emulation) - The model's only job is to map a detection rule to one technique in a pinned fork of Stratus Red Team; CI then detonates it in an isolated cloud account stamped with a run ID, searches the SIEM with the rule's query for that ID, and posts pass or fail on the pull request. Advisory rather than blocking, anomaly and correlation rules are skipped, and no counts of rules validated are given.
- [After Two Tencent Cloud Hackathons: How Pentest-Agent Harnesses Evolved](https://mp.weixin.qq.com/s/pbieEet9VCR5iLhjViokIA) - The Cairn author's cross-edition retrospective, in Chinese, reading every finalist's design as three layers, state, action, and control, and arguing that much harness machinery encodes distrust of the model that turns to dead weight as models improve; grounded in the two competitions' rosters and results.
- [AI Pentesting Agents in 2026](https://appsecsanta.com/research/ai-pentesting-agents-2026) - Field survey of 39 open-source pentesting agents across six architecture patterns, aggregating eight benchmarks into one finding: agents solve 87% of one-day CVEs handed a description but 13% of realistic ones, and multi-agent designs beat monolithic ones 4.3x. Makes the case that stars are not a quality signal and peer-reviewed benchmarks are.
- [Anthropic: How We Contain Claude Across Products](https://www.anthropic.com/research/how-we-contain-claude) - How claude.ai (gVisor container), Claude Code (Seatbelt or bubblewrap sandbox), and Cowork (local VM) contain agents, and where each broke: users approved about 93% of permission prompts, a phished prompt exfiltrated AWS credentials in 24 of 25 runs, and a file in a Cowork workspace uploaded data to an attacker's account through the allowlisted `api.anthropic.com`. Concludes that the standard isolation primitives held while Anthropic's own components around them, such as its allowlist proxy, failed.
- [Anthropic: Measuring LLMs' Impact on N-Day Exploits](https://www.anthropic.com/research/n-days) - Given only the public patch diff and pre- and post-fix builds in an offline container, Claude Mythos Preview built working code-execution exploits for 8 of 18 Firefox SpiderMonkey patches, the first in under an hour, and full SYSTEM privilege-escalation chains for 8 of 21 Windows kernel patches at about $2,000 each in API credits; grading requires the exploit to work on the vulnerable build and fail on the patched one.
- [Anthropic: Patterns and Problems in Emerging Multiagent Systems](https://www.anthropic.com/research/multiagent-systems) - Anthropic research on coordination failures and swarm behavior among agents, including a vulnerability-discovery experiment where a coordinated swarm found 266 vulnerabilities across 15 open-source projects against 21 for independent parallel agents.
- [AWS: AWS Security Agent Exploited 33 of 37 New Real-World CVEs](https://aws.amazon.com/blogs/security/aws-security-agent-now-part-of-aws-continuum-exploited-33-of-37-new-real-world-cves/) - Given only an endpoint and a one-line hint, with runtime CVE lookup disabled, the agent captured 35 of 37 flags within a 10-hour limit per target; a per-sample integrity audit cut that to 33 genuine exploits, on a benchmark AWS calls contamination-reduced, not contamination-free.
- [AWS: Configuring Your AI Vulnerability Harness, Part 2, the Steering File](https://aws.amazon.com/blogs/security/configuring-your-ai-vulnerability-harness-part-2-the-steering-file/) - A steering file that makes the model verify code paths before reporting and scores each finding from five binary evidence checks, then adjusts for deployed controls and threat intel; AWS reports about 30% of unsteered findings cited code that did not exist, and none with verify-first.
- [AWS: Inside AWS Security Agent, a Multi-Agent Architecture for Automated Penetration Testing](https://aws.amazon.com/blogs/security/inside-aws-security-agent-a-multi-agent-architecture-for-automated-penetration-testing/) - Baseline scanners and static per-risk tasks feed a planner that generates application-specific tasks for swarm workers, and candidate findings are re-validated against natural-language assertions written by security experts; reports 92.5% attack success on CVE-Bench with grader feedback, 80% without it, and 65% with a model whose knowledge cutoff predates the benchmark.
- [Beyond Success Rate: Cost-Aware Evaluation of Offensive and Defensive Security Agents](https://arxiv.org/abs/2607.15263) - Compares models at fixed spend on Cybench and Splunk BOTS v1: offensive success keeps climbing with compute, while the strongest defenders are near their best within about 20 tool calls and a weaker model spends over 100 calls to plateau lower. Claude Opus 4.8 led defense at 93.9% and $2.98 per 1,000 points; the argument is that defense tracks tool discipline, not volume.
- [Booz Allen: Cyber Weapon Index](https://www.boozallen.com/insights/cyber/cyber-weapon-index.html) - Benchmark of 18 U.S. and Chinese models run as autonomous attackers against a production-grade enterprise network, validated by network telemetry, finding that only one model completes the full kill chain today and most will within six months.
- [Cairn: Postmortem of the Only Team to Clear the Tencent Cloud AI Pentest Challenge](https://mp.weixin.qq.com/s/DlpEH7bVr0xi0VawPJs3XA) - The solo author's account, in Chinese, of building the blackboard harness in two weekends and first running it end to end at 4 AM on race day: five days on Opus and GPT cost 7,692 RMB and 1.09 billion tokens, cost per flag rose from 52 RMB on day one to 284 RMB on day three as concurrency went up, and the board was cleared only after a night of reading logs by hand and injecting human hints. Argues against role-split agents, RAG, and generic skills; the harness shipped one skill, for flag submission.
- [Cisco Talos: Choose Your Fighter, Selecting Models for Your AI SOC](https://blog.talosintelligence.com/choose-your-fighter-balancing-competing-requirements-to-select-models-for-your-ai-soc/) - Sixty-six model and reasoning-effort conditions on one SOC log-review task: more reasoning effort often did not raise scores, and format failures and refusals weighed as much as accuracy; one synthetic corpus, five rounds per condition, list-price costs.
- [Cloudflare: Build Your Own Vulnerability Harness](https://blog.cloudflare.com/build-your-own-vulnerability-harness/) - How Cloudflare grew a single audit skill into a fleet scanner across 128 repos in six weeks: externalized state in SQLite for resumability, each agent held under 25% of its context window, one model hunting and a different model judging, and deduplication given its own agents. Reports that a single skill run finds only about half the bugs of repeated runs.
- [Cloudflare: Defend Against Frontier Cyber Models](https://blog.cloudflare.com/frontier-model-defense/) - Cloudflare's defensive architecture for a world where models find, chain, and prove exploits faster than teams can patch: ML attack scoring ahead of signature rules, positive-security API schema validation, and containment as the layer that matters once a bug lands. The blue-team counterpart to the harness posts.
- [Cybersecurity AI: Evaluating Agentic Cybersecurity in Attack/Defense CTFs](https://arxiv.org/abs/2510.17521) - Alias Robotics put agents on both sides of 23 attack-defense CTF battlegrounds: defenders patched successfully 54.3% of the time against 28.3% offensive initial access, but the gap stopped being significant once defense also had to keep services available (23.9%) and stop every intrusion (15.2%).

- [Microsoft: Defense at AI Speed](https://www.microsoft.com/en-us/security/blog/2026/05/12/defense-at-ai-speed-microsofts-new-multi-model-agentic-security-system-tops-leading-industry-benchmark/) - The design of MDASH: prepare, scan, validate by debate, dedupe, and prove stages run by more than 100 specialized agents on mixed frontier and distilled models, self-reporting 88.45% on CyberGym Level 1 and 16 CVEs in one Patch Tuesday; private preview only.
- [Microsoft: Lessons From 59 Linux Kernel Bug Reports](https://www.microsoft.com/en-us/security/blog/2026/11/11/lessons-from-59-linux-kernel-bug-reports/) - Two weeks of MDASH scans over Linux kernel subsystems produced 26,502 raw findings, which screening agents cut to 11,769 and QEMU proof-of-concept agents to 621; experts then spent over four person-months turning those into 59 upstream reports, 33 CVEs, and eight confirmed root exploits, with 42.8% of the PoC-backed cases sharing a root cause with another.
- [NVIDIA: Building an Adaptive Agentic Cybersecurity System with NVIDIA Nemotron](https://developer.nvidia.com/blog/building-an-adaptive-agentic-cybersecurity-system-with-nvidia-nemotron/) - NVIDIA and CrowdStrike's red-blue loop on an isolated, Falcon-instrumented replica of NVIDIA infrastructure: red records an action trace, blue reconstructs it and writes detections through a six-step validation harness ending in replay and an independent judge, and red re-runs with a new seed to evade. Backtest-passing detections rose from 16.5% to 41.9%; one scenario family, no code.
- [OpenAI: The Defense Factory](https://openai.com/the-defense-factory/) - OpenAI's reference architecture for a continuous inventory, discovery, dynamic validation, ownership, and verified remediation loop, with sprint numbers: 37% of findings deduplicated, 0.81% false positives after runtime validation, 100% Codex-generated patches, 0.53% rolled back.
- [Ramp: 100 Vulnerabilities Patched With 0 Humans](https://engineering.ramp.com/post/100-vulnerabilities-patched-with-0-humans) - Ramp's detector, adversarial manager, validator, and fixer pipeline that found and fixed about 100 latent issues in a week, with manager agents rejecting 40% of proposals that humans confirmed were false positives.
- [Reverser Space: The Harness Matters](https://reverser.space/blog/the-harness-matters-ai-reverse-engineering/) - Same model, same AgentRE-Bench tasks, two harnesses: structured analysis tools over MCP cut reported tokens 33% and analysis calls 35% at a tied score across 130 runs.
- [Shopify: Building an Agentic Harness That Outlasts the Model](https://shopify.engineering/building-an-agentic-harness-that-outlasts-the-model) - Shopify's Dispatch harness partitions each codebase into chunks of 20% to 30% of the model's context window, runs one hunter per partition in parallel, and has a different model write and run integration tests as the exploitability oracle; over about six weeks it scanned more than 80 applications and produced over 300 findings, at $50 to $300 per full scan and $5 to $50 per diff scan.
- [Shopify: River, Autonomous Vulnerability Remediation](https://shopify.engineering/river-vulnerability-remediation) - Shopify's Slack-native remediation agent that revalidates patches against repository head, PR state, and tracker before acting, cutting the dependency vulnerability backlog about 70% in its first 11 days.
- [SIR-Bench: Evaluating Investigation Depth in Security Incident Response Agents](https://arxiv.org/abs/2604.12040) - AWS replays 129 real incident patterns in controlled cloud accounts to build 794 cases and scores agents on novel findings that only appear in secondary logs such as CloudTrail, with an adversarial judge that assumes nothing happened until the agent cites evidence; the authors' agent reaches 97.1% true-positive detection, 73.4% false-positive rejection, and 41.9% novel-finding coverage. No code released.
- [Tencent Xuanwu Lab: Tencent Xuanwu Atuin AI on CyberGym](https://xlab.tencent.com/en/2026/07/02/xuanwu-atuin-cybergym/) - A manager agent tracks failed hypotheses and crash-signature mismatches and dispatches subagents that follow encoded procedures for root-cause hunting and PoC construction; with GLM-5.1 it reproduced 1,265 of 1,506 CyberGym Level 1 tasks (84.0% pass@1) against the 68.7% Zhipu AI reported for the same model in Claude Code, after rerunning 127 trajectories caught making prohibited web lookups and withdrawing an earlier 85.1% run that had used post-patch feedback.
- [Towards Cybersecurity SuperIntelligence: What's the Best Harness for Cybersecurity?](https://arxiv.org/abs/2605.28334) - Benchmarks five agent scaffolds on 33 cybersecurity challenges and finds no single harness wins; a blackboard architecture combining structurally diverse scaffolds covers 57.6% of problems against 45.5% for the best individual scaffold.
- [Trail of Bits: Auditing in the Age of (Good Enough) AI](https://blog.trailofbits.com/2026/09/18/auditing-in-the-age-of-good-enough-ai/) - Six months of agents building an LSP server, a decompiler, a static analyzer, and a Lean model for the Miden zkVM before the review started, yielding a signature-forgery finding and 95 machine-checked proofs.
- [Trail of Bits: How We Use /goal to Find Bugs in Patch the Planet](https://blog.trailofbits.com/2026/07/28/how-we-use-goal-to-find-bugs-in-patch-the-planet/) - Field notes on Codex goal mode for bug hunting: one outcome per session, one session per attack surface, and a two-pass false-positive check where a different model must agree before a finding counts; practitioner guidance without run counts or baselines.
- [Trail of Bits: VMs Won't Contain Cyber-Capable Agents](https://blog.trailofbits.com/2026/08/26/vms-wont-contain-cyber-capable-agents/) - GPT 5.6-Cyber in Codex goal mode attempted three escapes from a QEMU/KVM guest on Debian 12, one through a libslirp CVE the distribution still ships and one chaining three then-unknown bugs over about 12 hours; one host, built without kernel mitigations, and Firecracker was crashed but not escaped.
- [Turning LLM Memory into Program Analysis](https://pwning.systems/posts/llm-memory-program-analysis/) - Reframes long-running vulnerability research as a Datalog problem so the model handles fuzzy fact extraction while a database does deterministic reasoning and auto-invalidates conclusions when premises change, cutting context 38x and beating full-context prompting on adversarial memory benchmarks.
- [Wiz: How to Evaluate AI Agent Cybersecurity Capabilities](https://www.wiz.io/blog/cyber-model-arena-ai-benchmark) - Method behind Wiz's Cyber Model Arena v3.9, 59 model-harness agents on 327 isolated challenges graded by code rather than an LLM judge: the same model moved a mean 5.1 pass@1 points between Claude Code and ADK React, average pass@1 ran from 78.0% on API tasks to 38.2% on code vulnerabilities, and Codex with GPT-6 Luna matched Claude Code with GPT-5.6 Sol at $0.05 against $8.29 per solve.
- [XBOW: Agents Built From Alloys](https://xbow.com/blog/alloy-agents) - Randomly switching between models from different providers on each step of one solver conversation, with each model treating the other's turns as its own, raised XBOW's solve rate on fixed benchmarks from 25% to 55%; two Sonnet 4.0 and Gemini 2.5 Pro alloy agents solved 68.8% against 57.5% for two Sonnet agents, while alloys of same-provider models only matched the average of their parts.
- [XBOW: Dead.Letter, How XBOW Found an Unauthenticated RCE on Exim](https://xbow.com/blog/dead-letter-cve-2026-45185-xbow-found-rce-exim) - A one-byte use-after-free write in Exim 4.97's TLS path (CVE-2026-45185), worked for seven days by an autonomous agent and by a researcher with an LLM; the agent exploited the builds with ASLR or PIE off but neither finished the production build, and the author concludes LLMs alone are not yet ready to write real-world exploits.
